# Agent Guide for my-bun-app

This Next.js project uses the App Router with React Server Components by default.

## Commands

### Development
- `bun run dev` - Start development server at http://localhost:3000
- `bun run build` - Build for production
- `bun run start` - Start production server
- `bun run lint` - Run ESLint

### Testing
Playwright is configured for end-to-end testing:
- `bun run test` - Run all Playwright tests
- `bun run test:ui` - Run tests with UI mode
- `bunx playwright test --project=chromium` - Run tests for specific browser
- `bunx playwright test tests/echo.spec.ts` - Run a single test file

## Project Structure

```
app/
  layout.tsx        # Root layout with fonts and metadata
  page.tsx          # Home page
  globals.css       # Global styles and Tailwind config
tests/
  echo.spec.ts      # Playwright end-to-end tests
public/             # Static assets (images, favicon)
```

## Code Style Guidelines

### TypeScript
- **Strict mode enabled** - All types must be properly defined
- Use `Readonly<>` wrapper for component props: `Readonly<{ children: React.ReactNode }>`
- Prefer named exports for components and types
- Export types inline or with `export type` when appropriate

```tsx
// Component with typed props
export default function Component({
  title,
}: Readonly<{
  title: string;
}>) {
  return <h1>{title}</h1>;
}

// Type export
export type Metadata = { title: string; description: string };
```

### Imports
- Use named imports for React utilities: `import type { Metadata } from "next"`
- Use relative imports with `./` prefix for local files
- Image imports use Next.js optimized component: `import Image from "next/image"`

```tsx
import type { Metadata } from "next";
import { Geist } from "next/font/google";
import "./globals.css";
```

### Components
- **Server components by default** - Don't add `"use client"` unless you need interactivity
- Functional components with TypeScript
- Props typed explicitly with interfaces or inline types
- Use `export default function` for component definitions

```tsx
export default function Home() {
  return (
    <div className="flex min-h-screen">
      <main className="w-full">
        <h1>Hello</h1>
      </main>
    </div>
  );
}
```

### Styling with Tailwind CSS v4
- Uses Tailwind CSS v4 with inline `@theme` configuration in globals.css
- Use utility classes via `className` prop
- Dark mode support with `dark:` prefix
- CSS variables for theming defined in `:root`

```tsx
// Responsive and dark mode styling
<div className="flex min-h-screen items-center justify-center bg-zinc-50 dark:bg-black">
  <h1 className="text-3xl font-semibold text-black dark:text-white">
    Heading
  </h1>
</div>
```

### CSS Variables & Theming
- Define colors in `:root` and `@media (prefers-color-scheme: dark)`
- Use CSS variables in Tailwind config via `@theme inline`
- Font variables: `--font-geist-sans`, `--font-geist-mono`

```css
:root {
  --background: #ffffff;
  --foreground: #171717;
}

@media (prefers-color-scheme: dark) {
  :root {
    --background: #0a0a0a;
    --foreground: #ededed;
  }
}

@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
}
```

### Images
- Use Next.js `Image` component for optimization
- Include `width` and `height` props
- Use `priority` for above-fold images
- Use `className="dark:invert"` for dark mode logo compatibility

```tsx
<Image
  className="dark:invert"
  src="/next.svg"
  alt="Next.js logo"
  width={100}
  height={20}
  priority
/>
```

### Fonts
- Use `next/font/google` for Google Fonts
- Create font instances with `variable` for CSS variable assignment

```tsx
const geistSans = Geist({
  variable: "--font-geist-sans",
  subsets: ["latin"],
});
```

### Metadata
- Export `metadata` object from route files
- Type with `Metadata` from `next`

```tsx
export const metadata: Metadata = {
  title: "Create Next App",
  description: "Generated by create next app",
};
```

### Path Aliases
- Use `@/*` alias for root directory imports (configured in tsconfig.json)
- Example: `import Button from "@/components/Button"`

### Type Safety
- Never use `as any`, `@ts-ignore`, or `@ts-expect-error`
- All types must be properly defined with TypeScript strict mode
- Use proper type guards for runtime type checking

### Error Handling
- Server components handle errors with React Error Boundaries
- Client components use try/catch for async operations
- Always handle promise rejections

## Linting

ESLint is configured with Next.js rules:
- ESLint v9 with flat config format
- Uses `eslint-config-next` with core-web-vitals and TypeScript rules
- Run `bun run lint` before committing

## Build Requirements

- Build passes with `bun run build`
- No TypeScript errors
- No ESLint errors
- All images have width/height attributes for Next.js Image component
